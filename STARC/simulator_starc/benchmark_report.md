# STARC "Remapping Wall" 벤치마크 결과 리포트

## 1. 개요
Reasoning LLM (DeepSeek-R1-Distill-Qwen-7B, 128d)의 장단기 문맥 (256 ~ 128K) 환경에서 기존 PIM 최적화 기법(STARC)의 클러스터링 및 물리적 데이터 재배치(Remapping) 오버헤드를 측정했습니다.

1K ~ 32K 데이터는 실측 벤치마크 결과이며, 64K 및 128K 데이터는 WSL OOM 한계로 인해 $O(L^2)$ 클러스터링 복잡도와 $O(L)$ 재배치 복잡도를 기반으로 분석적 외삽(Extrapolated)되었습니다.

## 4. 핵심 인사이트 및 분석

### 📍 Inversion Point (성능 역전 지점)
* **발생 지점**: **256 (사실상 모든 구간에서 역전 발생)**
* 256에서의 지연시간: Dense `0.606ms` < STARC `0.624ms`
* 256 토큰 환경에서는 KV Budget이 256이므로 삭제되는 토큰이 전혀 없음에도 불구하고, STARC의 동작 구조상 발생하는 기본 클러스터링/복사 오버헤드로 인해 Dense 모델보다도 느려집니다. 

### 📊 "Remapping Wall"의 근본 원인
문맥 길이가 길어질수록, 실제 어텐션 연산 시간($T_{comp}$)보다 클러스터링과 물리적 재배치 오버헤드가 폭발적으로 증가합니다.
* **128K 오버헤드 비율**: 연산 시간(`3.281ms`) 대비 오버헤드(`161.979ms`)가 **4937%**에 달합니다.
* 오버헤드의 구성 (128K 기준):
    * **Clustering ($O(L^2)$)**: `143.631ms` (88.7%) - K-means 기반의 $L \times L$ 유사도 연산 병목
    * **Physical Copy ($O(L)$)**: `18.348ms` (11.3%) - PIM 뱅크 구조상 발생하는 물리적 데이터 이동 병목

**결론**: 기존 STARC의 K-means 클러스터링과 물리적 재매핑 방식은 문맥 길이가 길어질수록 폭발적으로 증가하는 명확한 병목으로 작용합니다. "Remapping Wall" 가설이 실험 및 분석 데이터를 통해 완벽히 증명되었습니다.
